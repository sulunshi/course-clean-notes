# 2026-09-15｜第二周｜数据科学与知识工程｜通顺整理稿

## 第一节课

以前有位同学，他的导师也会起到一定作用。这个同学完成课程任务后，把它继续做成了一篇论文。最初我看他的论文已经有了一定基础，就告诉他再做一两个月应该可以发表。后来他确实继续做了下去，还拿这项成果申请了博士。当时学院评选优秀学生代表时，他也谈到了这门数据科学课。

他最终完成了一篇比较完整的论文或报告，并发表了文章。通过这段经历，他的学术能力得到了很大提升，之后拿到了包括新加坡国立大学、香港中文大学等学校的博士全奖。他读完博士、做完博士后，现在已经是大学里的助理教授，将来还有可能回来任教。这么多年，我遇到的这种例子也不多。我的意思不是要求每个人都必须发展到这个程度，而是说课程作业如果只是挂在那里、没有真正完成和发表，其实作用有限；真正把它继续做下去，才可能产生价值。

下面先说一下课程安排。上周我和其他几个班聊过，有的班考核设计得更难一些。我们这个班需要先建群，后面的通知和信息填写都会在群里完成。没有进群的同学要尽快联系认识的同学加入。去年有位同学直到课程快结束时都没有进群，很多信息没有及时收到，最后成绩也受到了影响。

大家还要尽快组队，原则上五个人一组。班里大约九十人，人数基本正好；特殊情况下也可以六个人一组。组内一定要提前分好工。你们这学期的课程相对少一些，下学期压力可能会更大，因为会开设不少新课。现在保留下来的课程大概包括深度学习、数据科学和网络计算，有些课程取消了，有些课程作了调整。调整后的新课可能要到明年春季才能选。

下面介绍这门数据科学课的主要内容。我们这里主要讲 Graph，也就是图。许多复杂系统都可以用图来表示。大家在数据结构、离散数学等课程中已经接触过图，因此对点、边以及它们之间的关系应该不陌生。

社交媒体就是很常见的例子。每个用户可以看作一个点，关注、好友或互动关系可以看作边。只要一个问题中存在实体，以及实体之间可以明确描述的关系，就可以考虑用图来建模。

自然语言也可以从图的角度理解。Transformer 会根据上下文建立词与词之间的联系，并利用上下文预测词语。一个词并不是孤立存在的，它与周围词语之间存在关系。语音和视频同样如此，一帧内部的内容存在关联，不同帧之间也会随时间发生变化，这些关系都可以尝试用图来描述。

天气预测也是一个例子。如果观察了半年的天气数据，就要考虑这段时间里有没有周期性、时序关系、突发事件以及其他外部因素。把不同时间、不同地点以及影响天气的因素联系起来，就可以形成一个时空图。大家可以继续想一想，在自己的研究或生活中，还有哪些具体问题适合用图来建模。

现在经常讲“万物互联”。只要强调“互联”，背后通常就存在值得研究的图结构。例如，不同传感器和设备之间可以相互连接，形成物联网。大家也可以反过来思考，有没有哪一种场景完全无法借助图来获得任何帮助。如果真能找到一个很有说服力的例子，我可以从九十五分起给你评分。

这门课可能对大家的科研有帮助。你们可以结合自己的研究问题，想一想哪些部分能够借助图方法。我们面对的很多复杂系统都可以用图来建模。离散数学中除了命题逻辑、数理逻辑等内容，还有很重要的一部分就是图论；树也可以看作一种特殊的图。所以大学里学习离散数学并不是没有用，只是当时学习集合、关系、范式等内容时，大家可能觉得枯燥，还没有看到它们在实际研究中的作用。

有同学提到痛觉、味觉等连续感觉应该如何表示。如果目标是模拟感觉，可以把空间和时间一起考虑，构造一个 spatio-temporal graph，也就是时空图。触觉、嗅觉等信号可能分布在空间中的不同位置，并随时间增强、变化或衰减。虽然原始感觉是连续的，但经过适当离散化以后，仍然可以从时空关系的角度建模。关键还是先明确究竟要解决什么具体问题。

我以前本科所在的学校有詹天佑学院，其中开设过一门“批判性思维”课。每个班大约二十人，由不同学院的老师参与授课。课堂形式比较开放，会做讨论、辩论等活动，重点是训练大家提出问题和分析问题。你们如果对这类内容感兴趣，也可以找一些相关的书看看，它可能会启发你们思考怎样定义问题、怎样提出更有价值的问题。

回到图这个主题。图并不局限于某一个领域。只要能识别实体、实体之间的关系，并且这些关系有助于解释问题，就可以尝试用图来描述。大家现在一时想不到自己的研究如何使用图也没有关系，之后可以继续从现实生活和科研任务中寻找例子。

例如，神经系统可以表示成神经元之间的连接网络。Internet 也可以看作一张巨大的网络图，其中有不同层级的路由器，路由器之间传输数据包。域名本身也具有层次结构，例如 cn、edu.cn，再到 bjtu.edu.cn。这样的结构和连接关系都可以用网络或图来表达。

Facebook，也就是现在的 Meta，也可以把用户及其好友关系构造成图。每个用户是一个点，两个用户之间如果存在好友关系，就连接一条边。Facebook 有数十亿用户，把这些关系全部绘制和分析出来并不简单。假设给你几十亿条关系数据，每一行只记录 A 与 B、C 与 D 是好友，让你把它们转化成可视化网络，普通程序很可能直接卡死。这正是数据可视化领域需要解决的问题。

数据可视化远远不只是给定 X、Y 后画一个散点图或曲线图。好的可视化需要处理大规模数据，还要把事情讲清楚。国内在这一方向做得很好的团队之一是北京大学袁晓如老师的团队。他们会把文学作品中的人物关系、历史朝代的迁徙过程、中国版图随时间的变化等内容制作成动态可视化。要做出这样的系统，需要把数据、程序和叙事结合起来。可视化不只是呈现一个结果，还要帮助人理解结果背后的过程。

面对这些复杂系统，我们总要尝试理解它们。神经元之间的信息传递、互联网中的路由、社交网络中的关系，以及自然语言中的上下文，本质上都包含连接关系。

早期的语言模型会利用上下文预测词语。例如，把一句话中间的词遮住，根据周围词语预测空缺内容；或者根据前面已经出现的词预测下一个词。当句子中出现“天气”时，后面可能出现“晴朗”等相关词。这些方法都依赖词与词之间的关系。

我前段时间参加会议，听到有团队长期研究自动批改高考试卷。他们把语文试卷拍照输入系统，让 AI 识别答案、评分，甚至尝试处理作文。这个例子也很有意思，因为智能系统最核心的一步仍然是理解语言。

几年前，很多做数据挖掘的人会说自己在做 NLP；再过一段时间，大家又开始说自己在做 LLM。现在很少有人只笼统地说自己做大语言模型，更多人会说自己研究多智能体交互或各种 Agent。研究热点一直在变化，但语言理解仍然是基础。

现在使用大模型进行科研时，Prompt 非常重要。模型本身的基础能力当然重要，但你怎样表达任务、怎样拆解问题，往往会直接影响结果。例如，你可以给模型五篇论文，同时提供相应的 GitHub 代码，再让它尝试复现某篇论文。它未必能一次完整复现，但通常能够承担一部分整理、分析和执行工作。

更有效的做法是把研究任务拆开，并清楚告诉模型每份材料的用途。比如，第一、第二篇论文的思路对你的 idea 有帮助；第三、第四篇论文的实验设置比较完整，可以作为实验设计参考；第五篇论文的写作方式很好，可以作为表达参考。你还可以进一步指出前两篇论文的主要优点、现有不足，以及可能加入哪些改进。任务分得越清楚，模型完成得通常越好。

因此，只会等待老师或老板把第一步、第二步、第三步全部列出来，然后照着执行的人，未来可能更容易被替代。相反，一个人即使编程能力没有那么突出，只要有想法、会定义问题、能够清楚表达，也可能更有优势。这又回到了 Prompt，因为 Prompt 涉及自然语言理解，也就是 NLU，Natural Language Understanding。

自然语言理解非常困难，中文尤其如此。中文存在一词多义、语境省略以及相同表达在不同场合含义不同等问题。如果系统连用户说的第一句话都不能正确理解，后面的任务也就无法继续完成。

许多系统都可以用 Network 或 Graph 建模。社交网络中的微信、微博、小红书、抖音等平台，都会分析用户之间的关注、互动和传播关系。不过传统社交网络分析已经比较成熟，单纯研究这类问题的热度正在下降。现在更常见的方向是 LLM for Graph 和 Graph for LLM。

LLM for Graph 是用大语言模型帮助解决图上的问题；Graph for LLM 则是利用图结构改进大语言模型。大家可能听说过 RAG。大模型存在幻觉问题，可以通过检索已有知识，或者引入知识图谱中的结构化约束，减少模型随意生成错误内容的情况。图中的实体关系相当于给模型加上一些边界，使它不容易完全脱离已有知识。

学术引文网络也是重要的信息网络。论文之间通过引用关系连接起来，其中包含大量知识。数据挖掘领域早期有不少工作就来自学术引文网络，因为这类数据相对规范、关系也比较清楚。

写毕业论文时，可能需要引用三十篇左右的文献，而且这些文献应该经过筛选。导师给你一篇文章后，不能读完就结束，还要继续看它引用了哪些代表性工作、还有哪些团队研究同一问题，以及后续出现了哪些改进。如果这是一篇较好的论文，它通常会列出此前有代表性的 baseline 和相关工作。你还应该继续查看近几年发表的论文，找到其中被反复引用的工作。

很多研究图问题的论文都会引用关于 Power Law，也就是幂律分布的经典工作。这就是引文网络的价值。学术论文不同于微博、散文、日记或普通博客。论文需要把问题讲清楚，语言要经过打磨，方法要解释明白，引用也要相对严谨。

论文发表以后，其他研究者可能会引用、评价或质疑它。这和在社交平台发布内容后被转发、评论、点赞有些相似。一篇论文可能获得成百上千甚至更多引用。由于论文及其引用关系相对规范，这些数据很适合用于数据挖掘。

清华大学的唐杰老师早期就做过 AMiner。AMiner 会收集 Google Scholar、DBLP 等学术平台上的数据，构建作者、论文、机构和合作关系等学术网络。比如，要整理北京交通大学一位名叫王伟的老师的全部成果，并不容易，因为可能存在许多同名作者。只看姓名和单位仍然可能混淆，还要结合学院、合作者、研究方向等信息判断是不是同一个人。

如果一位作者经常和计算机学院的研究者合作，他可能来自计算机领域，但也不能因此排除他来自电信等其他学院。判断一个学生或老师的真实身份，需要综合学号、学院、合作者和研究主题等多种信息。AMiner 所解决的一个核心问题，就是把这些学术实体及其关系整理清楚。

唐杰老师后来在大模型方向取得成功并非偶然。早期做学术网络时，他就意识到高质量数据是一个很大的问题。以前研究者为了获得一份特殊数据，可能需要自己持续采集和清洗很多年，最后只开放其中一部分。现在大家经常在论文中看到“code and data are available”，但实际复现时会发现，代码和数据未必真的容易使用。

公开代码可能经过多层封装，缺少依赖、参数或关键处理步骤；公开数据也可能只是模型已经预处理好的中间结果。你可以把中间文件直接送入模型得到论文中的结果，但如果想在原研究基础上加入新的信息或提出新的 idea，这份数据往往就不够用了。作者可能保留了更完整的原始数据，也可能正在利用这些数据继续开展其他研究。

现在已经有人尝试用 Agent 辅助论文复现。把论文交给 Agent 后，它可以分析需要完成哪些步骤。尤其是在生物、基因等专业领域，研究者需要记录很多实验维度，跨领域人员未必清楚所有细节，专业 Agent 可能在任务拆解和流程检查上发挥作用。

科研复现非常重要。学生告诉老师 baseline 是 91，自己的结果是 93.6，看起来提高了两个多点，老师通常会觉得结果很好，让他继续做。但如果后面的多个实验结果都特别好，老师反而可能心里没底，因为老师不可能亲自把每个实验全部复现一遍，只能在一定程度上相信学生。

如果论文发表后被发现存在问题，学生和老师都会受到影响，通讯作者尤其要承担责任。很多老师可能只是看过论文、提出修改意见，并没有亲自运行全部实验，但论文一旦出现造假或严重错误，仍然会产生很大麻烦。因此，研究团队很需要可靠的自动复现和检查工具。

现实中复现论文经常遇到困难。论文说某个方法达到了 93.6，baseline 是 89，但你实际运行时可能得到 86、89或91，就是得不到93.6。你给作者写邮件也可能得不到回复；过了三四年，原来的学生已经毕业，代码环境也无法重新搭建，这时就很难判断究竟是参数设置不同、环境失效，还是论文结果本身存在问题。

调参同样存在边界。如果运行一次得到91，不能因为反复运行和调参一万次后偶然得到一个更高结果，就只报告最好的一次。正常调参和选择性报告之间必须有清楚的规范，否则研究结果就不再可靠。

最近我也接触到一些做人工智能投资的人。他们提到，接下来可能会投资数据相关公司，但这里的数据业务不只是简单爬取数据，更重要的是数据质量、数据治理以及高质量数据的生产和验证。大模型的发展让大家重新认识到，数据本身仍然非常重要。

疾病传播网络也是图的重要应用。一个人感染疾病后，可能把疾病传给与他接触的若干人。在疫情期间，很多研究会分析传播路径以及如何控制传播。隔离当然可以减少传播，但隔离所有人的成本非常高。因此需要研究怎样以尽可能小的隔离代价，获得尽可能大的传播抑制效果。这类问题非常适合在网络模型上研究。

今天已经给大家介绍了不少例子。希望你们继续思考自己的研究中有没有适合用图表示的问题。随着课程推进，大家会逐渐发现，数据科学可以围绕 Graph 展开。图是一种通用语言，能够表达各种复杂数据；它也是跨领域交流的通用词汇。计算机领域、社会科学、物理学等不同方向的研究者谈到 Graph 时，都能够理解点、边和关系这些基本概念，因此比较容易相互交流。

我们先休息一会儿。

## 第二节课

构建网络以后，我们可以研究两个节点之间是否存在路径，也可以计算连接两个节点至少需要经过多少步。两个节点可能完全无法连接，但在很多现实网络中，经常会出现“他认识他，他又认识另一个人”的间接联系。

很多年前，人们提出过“六度分隔”。后来有研究者利用大规模社交网络做了验证。2011 年的一项研究发现，用户之间平均不需要经过六次跳转，大约经过四次就能建立联系，所以研究题目就叫 Four Degrees of Separation。原始结果大约是 3.8 跳；后来又有人继续做类似实验，发现平均距离已经接近三跳。

这说明什么问题？过去讲六度分隔，后来变成四度分隔，平均距离还在继续缩短，说明人与人之间的联系越来越紧密，整个网络也越来越稠密，也就是越来越 dense。

你们以前学习的很多课程，现在都可以重新想一想它们有什么用。例如微积分、概率论、矩阵分析、线性代数和随机过程，在数据科学研究中都会用到。读本科时可能觉得这些课程没什么用，我当学生时也有过这种感觉。后来读到博士后半段，才越来越体会到它们的重要性，又重新复习了微积分、线性代数、概率统计和随机过程，感受就很不一样。

图算法也是如此。数据结构课里应该讲过最小生成树，包括 Prim 和 Kruskal 算法。面对一个非常稠密的图和一个比较稀疏的图，适合使用的算法可能不同。网络越来越 dense 以后，不只是理论结论发生变化，实际计算方法也需要调整。

这里还会涉及“小世界”，也就是 small-world network。它与日常所说的“世界真小”并不完全相同，而是一个专门的网络模型。后面会有一节课专门讲小世界模型。这个模型有意思的地方在于，它试图解释大量局部联系怎样逐渐形成一个整体上距离很短的网络。

以我们班为例，现在大约有九十个人。刚入学时，除了本校同学、一起考研或提前联系过的人，大家彼此之间可能没有多少联系。研究生之间的联系可能还不如本科生密切，因为大家不一定住在同一个宿舍，每天的生活也比较分散。

但随着时间推移，你会逐渐认识更多人。假设一个学院有两百名学生，每个人的微信账号是一个节点，两个人互为好友就连接一条边。刚入学时画出这张图，边可能很少；四年以后再画一次，结构会完全不同。有些人属于同一个小组，有些人住在同一宿舍，有些人参加过同一项活动，还有些人因为打球、唱歌或其他兴趣建立了联系。

如果能够构造一个模型，以刚入学时的网络为输入，让它运行一段时间后收敛到与四年后真实网络相近的状态，就相当于理解了这个网络演化中的部分规律。网络科学中的很多模型都在尝试做类似的事情。后面我们还会讲随机图模型。模型本身可能并不复杂，但有时能产生与现实网络很相似的结果。

大家还可以继续思考，网络不断演化，最后会达到什么状态。这个问题在学术界和工业界的关注方式并不完全相同。我们经常说学术界与工业界之间存在很大的 gap。

学术界喜欢研究复杂模型，并把结果发表在顶级会议上，但真正能够落地的成果并不多。我与华为、美团、中航信等企业有过合作。企业提出的需求往往很具体，甚至看起来比较简单，但很多学术模型真正放进生产系统以后并不能工作。过去双方甚至会互相看不上。学术界的人可能觉得工业界使用的逻辑回归、特征工程太简单；工业界的人则会觉得很多论文只会讲故事，模型太复杂，无法上线。

我读博士时听过一位阿里搜索团队的专家作报告。当时双十一已经很火，大家原以为阿里的搜索和推荐一定用了非常复杂的模型。结果听完以后很震惊，他们使用的核心模型可能只是线性回归，真正投入大量精力的是特征工程。

他们可以构造上万种特征，再把这些特征两两、三三或四四组合，产生数百万维的新特征。很多组合未必有直观含义，但借助阿里云的计算能力，最终做出的搜索和“猜你喜欢”等功能效果不错。模型本身并不复杂，强大的是数据、特征和计算系统。

工业系统最看重的是稳定、可靠和可承受的运行成本。论文模型即使离线指标从 85 提升到 92，如果上线后延迟增加、系统卡死，仍然没有价值。对于一个每秒要处理几十万、上百万甚至更多请求的系统来说，最简单、最可靠的方法常常更合适。企业宁愿稳定达到 80 分，也不一定愿意为一个不可靠的 92 分模型承担巨大风险。

反过来，工业界的人也可能不理解学术研究为什么要把问题包装得如此复杂。论文需要说明问题的重要性、提出关键挑战，并解释方法怎样解决这些挑战；但到了真实系统中，还要继续回答模型能不能在千万级数据和高并发条件下运行。双方关注的目标不同，因此长期存在鸿沟。

现在有了大模型和智能体，这种鸿沟可能会缩小一些。工业界的人更容易使用一些先进方法，学术研究也更容易制作原型。但读论文仍然是基本能力。很多学生读一篇论文读了一个月，做出一份 PPT，自认为已经读懂了。可是在组会上，只要别人问公式中的某个符号是什么意思，为什么这里要用 Sigmoid，往往就回答不出来。

真正读懂论文，需要能够解释每个关键概念、公式和设计选择。刚开始时大家容易产生一种错觉，觉得自己什么都读懂了；再深入一些，反而会发现还有很多问题没有理解。这是正常过程。

下面看社群或者圈层结构。国家和网络平台都很关注特定群体的识别，例如网络诈骗团伙。已知一个可疑账号后，能不能沿着它的关系网络找出整个团伙？这时可能会想到聚类等方法，但现实情况远比简单聚类复杂。

一个人通常同时属于多个圈子。你的大学同学是一个圈子，高中同学是一个圈子，家人是一个圈子，同一个班、同一宿舍、同一兴趣小组又可能分别形成更小的圈子。这些圈子不是完全独立的，它们会通过某些人交织在一起。

这里会涉及强连接和弱连接。父母、家人以及经常联系的好朋友属于强连接，例如每天或每周都会交流的人。参加活动时偶然认识、加了微信但平时很少联系的人，可以看作弱连接。

研究发现，在获得新信息，尤其是寻找就业机会时，弱连接有时比强连接更有价值。原因是宿舍同学、家人和密友与你处在相近的信息环境里，他们知道的消息你大概率也知道。参加招聘会或行业活动时认识的人，平时联系不多，却可能突然发布实习或招聘信息。这类信息能够跨越原来的圈子传递给你。

社会网络还被用于分析心理健康问题。美国一些研究会比较抑郁、自闭或具有自伤倾向的青少年与其他人的社交结构。不过这些研究结论未必完全准确，只能作为一种观察。

一种可能的现象是，社交状态较好的人往往参加多个兴趣圈子，而且这些圈子彼此会发生交叉。例如，一个人喜欢打篮球，也喜欢唱歌和美食。他组织活动时会带来其他圈子的朋友，朋友又会带来新的人，于是原本不同的圈子逐渐连接起来。现实中的很多社交圈并不是相互隔离的，而是交织在一起。

随着年龄增长，大家会越来越明显地感觉到专业圈子其实很小。在国内较好的高校中，计算机、软件、网络安全和人工智能等相关方向的老师，通常通过一两层关系就能联系起来。工业界也类似，在华为、阿里、小米等公司工作多年后，很多人即使不直接认识，也能通过共同同事建立联系。

到了三四十岁，如果一个人在自己的专业领域里谁都不认识，也没有人知道他，只是长期做重复性工作，发展可能会比较受限。关系网络的作用并不是要求大家刻意攀附，而是说明职业选择和个人信誉都会通过网络传播。

我身边最近就有一个学生面临升学选择。一位老师愿意给他直博面试机会，但要求一旦确定就签署比较严格的协议。学生如果后来反悔，不只会影响自己，也可能影响推荐他的老师和原学校。你可能以为拉黑微信、换一所学校就可以结束，但两个学校的老师很可能通过一层关系就认识。网络中的选择会产生连带影响，所以作决定前一定要想清楚。

下面看电力网络。美国东海岸曾发生过大规模停电，一个局部故障通过网络产生 cascade failure，也就是级联失效，最后影响了整个区域。电力系统中如果存在少数关键节点，一旦这些节点遭到破坏，整个网络都可能瘫痪。因此，系统必须考虑怎样设计结构，才能避免单点故障扩散。

分布式系统中也有类似思想。大家学过 HDFS，其中会使用副本和心跳机制。系统不断发送心跳，一旦某个节点长时间没有响应，就启动替代方案。副本、冗余和备份的成本很高，也会产生额外通信负担，但它们可以避免一个节点失效后整个系统停止运行。

企业管理也会借鉴这种思想。例如，有些公司要求部门负责人提前培养一名 backup。当负责人跳槽、离职、生病或工作表现不佳时，候选人可以接替岗位。这个人不能由负责人随便指定，还要经过团队投票、HR 和上级审核。

从公司整体利益看，这种制度可以降低关键岗位突然空缺的风险；但对基层管理者很不友好，因为他会感觉自己随时可以被替代。这说明同一个网络机制对系统整体可能有利，对单个节点却不一定友好。

网络中还有关键节点攻击问题。如果攻击少量节点，就能让整个系统发生很大变化，那么这些节点就是系统的薄弱环节。机器学习中的对抗攻击也有类似思想：只修改图片中很少的像素，甚至不超过五个像素，就可能让模型作出完全不同的预测。研究者关心怎样以最小代价造成最大影响，也关心怎样提高系统的鲁棒性。

另一个相关主题是 misinformation，也就是错误信息。Wikipedia 的词条通常比较权威，但有人会恶意修改词条或添加虚假内容。为了评估检测算法，可以有控制地构造一些假的词条或错误信息，再观察人和算法能否识别出来。图结构在这类识别任务中很重要，因为错误信息不只是文本内容有问题，它的编辑者、传播者和引用关系也可能表现出异常。

社交媒体里还有大量机器人账号，也叫 social bots。早期的“僵尸粉”比较容易识别。一个账号关注了两三千人，却只有十几个粉丝，发布的内容质量又很低，很可能就是僵尸账号。现在的机器人高级得多，单看主页和内容可能已经很难判断。

我们正在参与一个相关项目，用社交机器人评估推荐算法是否公平，以及算法会不会造成信息茧房。以短视频平台为例，你连续观看或收藏某类内容，系统就会不断推荐相似内容。短期看，这能提高用户停留时间；长期看，用户可能只接触到单一观点，被困在信息茧房里。

这个实验很难直接在人身上做。一个人是否进入信息茧房，往往只有他自己能够感受到，而且这种主观状态也很难通过公开数据完整采集。研究者因此会建立 sandbox，也就是沙箱环境，制作一个内部的小型社交平台，把不同推荐算法放进去，再注入大量 Agent 充当社交机器人。

现在的 Agent 不只会机械发帖，还会被设定人格、目标、情绪和行动策略，使它尽量像真实用户一样活动。例如，研究者可能希望它逐步进入某个可疑组织。它不能一上来就直接询问敏感信息，否则马上会被识别；它需要先浏览内容、参与讨论、建立关系，之后才可能获得更深层的信息。

这与打击网络黑灰产和传销组织有一定关系。现实中的诈骗团伙具有很强的反渗透能力，对新账号和陌生人非常警惕。有些老年人、学生等群体仍然容易受到诈骗。要进入这类网络并收集有效信息，机器人必须表现得像真实用户，甚至需要展示适当的情绪反应。

客服场景也能说明这一点。现在和你聊天的客服有时完全是机器人，有时是机器人与人工混合。它会使用礼貌用语，也会模仿人的停顿和表达，使用户很难判断对方究竟是不是机器。

如果 Agent 能够较真实地进入网络组织，就可能帮助公安等部门获得更多线索。许多网络诈骗组织位于境外，很难直接通过物理方式处理，只能更多依靠技术手段进行识别、渗透和对抗。

网络黑灰产还可能组织大量账号同时攻击某个用户或直播间。过去这类“账号轰炸”需要房间里摆很多手机，由大量人员操作；现在可以由 Agent 批量控制账号，在很短时间内刷同样的内容、带节奏，使一个正常账号无法继续运营。

防守方也可以使用算法和机器人进行对抗。攻击方调动一批账号集中带节奏，防守方可以识别这些账号，并部署另一批自动化账号稀释或阻断传播，使讨论不再完全按照攻击方设计的方向发展。这种对抗可能达到几十万甚至更大的账号规模。

检测社交机器人不能只看它发布了什么。如果一个账号看起来可疑，我们通常会继续查看它关注了谁、谁关注它、有哪些共同关注者，以及它与其他账号之间的互动关系。单个账号的内容可以伪装，但整个关系网络更难完全伪造，所以图算法在机器人检测中很重要。

日常使用社交平台时也能感受到这一点。平台可能根据关注关系和共同联系人，把同学、老师或熟人推荐给你。即使账号名称陌生，通过共同关注和粉丝关系，也可能大致猜出对方是谁。

但共同好友推荐并不总能改善体验。假设两个人曾经是情侣，他们拥有二十多个共同好友。分手并互相删除以后，系统仍然可能因为共同好友太多，反复推荐对方。对算法来说，这是一次高概率的好友预测；对用户来说，却可能是非常糟糕的体验。怎样识别这种特殊关系并避免不合适的推荐，是算法设计中的真实难题。

图算法还广泛应用于电商推荐。如果两件商品经常被同一批用户购买，它们之间就可以建立关联。当用户购买其中一件商品时，系统会推荐另一件。这是基于共现关系构建商品网络的一种简单思路。

网络上的观点演化也可以建模。一个热点事件出现后，可能有一部分人支持，一部分人反对，还有一部分人保持中立和观望。随着新信息不断出现，三类人的比例会随时间变化。刚开始可能几乎所有人都支持某一方，第二天又出现新材料，舆论颜色很快发生反转。

不同群体会相互影响。真正容易被争取的往往不是立场非常坚定的两端，而是中间的观望者。比如两位明星的粉丝发生争论，双方核心粉丝很难被对方说服；没有明确立场的普通用户更可能因为接触到的信息而改变看法。研究者关心怎样描述这种影响过程，以及怎样用有限资源改变观点传播的结果。

如果一个人在现实中遭遇不公平待遇，希望在网络上引起关注，只靠自己发布内容通常很难形成影响。更有效的方式可能是先找到关注相关议题的人，特别是有传播能力的大 V，请他们转发，再通过关系网络把信息扩散出去。这同样是网络传播问题，关键不只是内容本身，还包括由谁发布、谁愿意转发，以及信息能够进入哪些圈层。

今天我们主要从路径、小世界、强弱连接、社群结构、级联失效、关键节点攻击、错误信息、社交机器人、推荐系统和观点传播等方面，看了图与网络的应用。大家可以继续从自己的研究和生活中寻找问题，思考其中有哪些实体、关系和传播过程，以及能否用 Graph 建立模型。我们下周继续。
