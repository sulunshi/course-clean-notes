# 2026-09-17｜第二周｜专业英语｜通顺整理稿

## 第一节课

### 一、课程介绍

这门课是面向软件工程专业研究生开设的专业英语课程。课程会围绕听、说、读、写四个方面展开，其中课堂上的口语表达和互动会占较多时间。大家如果有问题，可以随时提问，也欢迎积极参与讨论。开口时不必过分担心发音、语法或词汇不够完美，重要的是保持开放心态，在练习中逐渐提高。

学习专业英语并不只是为了通过一门课。软件工程领域的大量技术文章、编程文档、开源社区资料和第一手技术资源都以英文呈现。将来写论文、参加国际会议、进行问答交流、参与国际化项目或求职面试，都需要阅读、写作、演讲和沟通能力。学习一门语言也意味着打开观察世界的另一扇窗口，接触不同的表达方式和价值观。

### 二、课程目标与能力培养

课程首先希望大家掌握软件工程领域的核心术语，理解技术文本的表达方式和语言特征，了解学术论文语言以及新兴技术的相关表达，并关注国际发展趋势和开源社区动态。

在听力方面，除了课堂训练，大家还可以在课下收听专业播客、访谈和前沿技术对谈。在阅读方面，需要学习阅读技术文章和学术论文，并逐渐形成批判性阅读能力。在口语方面，课程会安排课堂发言和展示，训练专业交流与演讲能力。在写作方面，既包括学术文章和技术文章，也包括专业邮件、需求文档、设计文档和用户手册等常见材料。

现在可以使用 AI 辅助写作，但不能让 AI 直接替代自己的专业英语能力。使用 AI 时，需要判断它给出的内容是否正确，并说明自己如何借助 AI 改进表达。越是频繁使用 AI，越要培养批判性思维，包括分析与评价、论证与反驳以及独立表达的能力。

课程还希望大家形成跨文化交流意识、终身学习习惯和基本的社会责任意识。专业英语不可能只靠十六周完全掌握，课程结束后仍需要持续练习。

### 三、主要学习内容

课程内容主要包括专业语言、文献阅读、听说训练、写作训练和跨文化沟通。

专业语言部分会学习软件工程术语、常用句式以及技术英语的语言特征。文献阅读部分涉及技术文档、学术论文和前沿报告。技术文档包括 requirements、design documents 和 user manuals 等；学术写作会涉及摘要、论文结构、研究报告、批判性观点以及对研究成果的评价与反驳。

课堂还会讨论如何使用 AI 辅助写作、如何判断 AI 生成内容，以及怎样避免把 AI 的输出直接当作自己的成果。写作应当做到清楚、简洁和正确，同时考虑跨文化交流中的表达是否得体。【疑似：老师将这些要求概括为写作的 4C 原则。】

### 四、考核方式与学习要求

这门课没有期末闭卷考试，主要采用过程性考核。平时表现约占 10%，包括出勤、课堂参与和课堂任务；专业阅读约占 20%，其中还会安排同伴互评；演讲或展示约占 25%，评价内容包括内容组织、语言流畅度和演示材料表达；技术写作约占 25%。其余部分还会结合听、说、读、写任务和协作任务进行评价。【具体比例以教师后续发布的正式要求为准。】

AI 可以作为辅助工具，但提交作业时需要附上 AI 使用说明，说明自己如何与 AI 协作并提升专业英语能力，而不是让 AI 完成全部工作。

老师推荐的资源包括专业英语写作教材、IEEE Writing Guide、科学写作和演讲方面的书籍，例如 *The Craft of Scientific Writing*、*Style: Lessons in Clarity and Grace*、*Presentation Zen* 和 *The Culture Map*。还可以通过 Stack Overflow、技术视频、学术平台和 Grammarly 等资源练习。与此同时，也要关注中国技术创新的国际表达，例如 HarmonyOS 等技术如何用英文对外介绍。

老师引用了一句话作为课程寄语：*The limits of my language are the limits of my world.* 语言的边界也会影响我们认识世界的边界。

### 五、第一讲：软件工程专业词汇的构词规律

软件工程文档和开源社区大量使用英文，因此理解专业词汇的构成方式十分重要。第一类是前缀构词。例如，`re-` 常表示 again 或 back，可见于 rebuild、redevelop、redeploy 等词；`de-` 常表示 remove 或 reverse，可见于 decompose 等词。课堂还提到了 `pre-`、`post-`、`inter-` 和 `micro-` 等常见前缀，要求大家结合已有专业词汇主动举例。

第二类是后缀构词。`-able` 或 `-ible` 常表示具有某种能力或可能性，例如 reusable、maintainable；`-tion` 或 `-sion` 常把动作或过程转为名词，例如 calculation、optimization；`-ize` 常表示使事物发生某种变化，例如 serialize；`-ment` 常构成表示过程或结果的名词，例如 deployment、assignment；`-ity` 常表示性质或状态，例如 compatibility、security。

第三类是合成词。技术词汇中常见名词加名词、形容词加名词等组合，例如 database management、cloud computing、artificial intelligence 和 distributed system。理解中心词和修饰成分之间的关系，有助于读懂较长的专业名词短语。

### 六、常见缩略语与软件工程表达

课堂列举了若干常见缩略语：

- API：Application Programming Interface
- SDK：Software Development Kit
- IDE：Integrated Development Environment
- CI：Continuous Integration
- CD：【结合语境可能指 Continuous Delivery 或 Continuous Deployment】
- SDLC：Software Development Life Cycle
- QA：Quality Assurance

需求可以分为功能性需求和非功能性需求。功能性需求描述系统要提供的功能，常与 features、user stories、use cases 和 business logic 有关。非功能性需求关注 performance、security、usability 和 reliability 等质量属性。

用户故事通常采用类似 “As a role, I want a feature, so that I can obtain a benefit” 的结构，用来说明角色、需求和价值。课堂还提到了 SOLID 原则中的 Interface Segregation Principle 和 Dependency Inversion Principle，并介绍了 unit testing、integration testing、system testing、end-to-end testing，以及 TDD 和 BDD 等开发与测试相关表达。

老师提醒大家，AI 可以帮助查询术语，但语言学习仍然需要自己思考和练习。只有亲自回忆、举例和使用这些词汇，才能形成稳定的记忆。

### 一、技术表达要准确、客观

在技术写作中，像 “pretty good” 或 “works fine” 这样的表达不够准确。读者会追问：究竟好在哪里，在哪些条件下运行良好，依据是什么。技术文本应尽量把对象、条件、指标和结果说清楚。例如，可以用 “The method demonstrates effectiveness” 或 “The analysis indicates improved performance” 这类基于方法、分析或结果的表达，替代单纯的个人判断。

技术英语中还经常出现较长的名词短语。阅读时要先找到中心词，再分析前面的修饰成分。例如，cloud-based、microservices-based 等成分通常说明技术基础或实现方式。遇到复杂结构时，不要按单词顺序生硬翻译，而要先确定各个修饰语与中心词的关系。【原始转写中的完整例句识别不清，只能确认其中出现了 cloud-based 和疑似 microservices-based 的结构。】

### 二、段落要按照逻辑展开

一段技术文字通常先提出 main idea 或 main concept，再用 key points、数据或例子加以支持，最后说明由此得到的结果或推论。例如，先说明某项预测为何可能实现，再补充 machine learning 相关的技术细节。

段落内部和段落之间都需要清楚的逻辑关系。课堂介绍了 PEEL 结构：

- P：Point，提出本段的主要观点或 topic sentence。
- E：Evidence，给出数据、事实或例子支持观点。
- E：Explanation，解释证据如何支持观点。
- L：Link，把本段结论与主题或下一段联系起来。

写作时还可以从现有 limitations 或 challenges 引出新的 problem，再对问题进行分析、给出细节和 justification，使论证形成连续的逻辑链条。

### 三、减少主观化和绝对化表达

学术写作应尽量避免 “I think the method is good” 或 “We believe this method works” 这类以个人态度为中心的表达。更合适的方式是让证据、方法或分析成为句子的主语，例如：

- The method demonstrates effectiveness.
- The results indicate improved performance.
- The analysis suggests that the method works.

技术结论也不宜说得过于绝对。与 “This definitely improves performance” 相比，“This approach tends to improve performance” 更谨慎。常见的缓和表达包括 `appears to`、`suggests that` 和 `tends to`。这些表达不是削弱论证，而是在证据允许的范围内准确陈述结论。

### 四、论文不同部分的表达任务

论文的引言、方法和结果部分承担不同任务，因此语言倾向也不同。引言通常从研究背景出发，可以用 “Recent advances in + 研究领域” 引入领域发展，再指出已有研究、存在的问题以及本文工作的主要贡献。方法部分需要清楚说明采用的步骤、技术和实验配置。结果部分则应使用具体数据或指标说明发现，避免只用笼统评价。

组织全文时要使用合适的连接词表示顺序、因果和结论，例如 first、then、as a result 和 therefore。连接词的作用是把观点、证据、解释和结论连成清楚的论证过程，而不是机械地堆在句首。
